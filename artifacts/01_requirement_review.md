# Артефакт 01. Ревью требований ArtCase

Выполнено по скиллу `requirement_review.md` на реестре `00_requirements_registry.md`.

## Находки ревью

| ID | Тип | Требование | Описание | Серьёзность | Рекомендация |
|---|---|---|---|---|---|
| F-01 | AMB | API-1, OS-1 | «Примерно 30%» — точная вероятность не задана; поведение недетерминировано, критерий прохождения теста неопределим | Major | Зафиксировать верхнюю границу вероятности и требование к клиенту (retry-политика) |
| F-02 | AMB | DR-2, DR-3, DR-4 | «До 255 символов» — не указано, включительно ли 255; не описано поведение при превышении (фактически — ошибка СУБД 500) | Major | Уточнить границу включительно и требование к клиенту по контролю длины |
| F-03 | AMB | DR-4, API-6 | Формат тегов не задан: разделитель, регистр; поиск «по вхождению подстроки» найдёт «cit» по тегу «city» — ожидаемо ли это | Major | Специфицировать формат тегов и семантику поиска |
| F-04 | AMB | API-3, API-4, OS-2 | Ответ «200 с пустым телом (null)» неотличим от «пустой объект»: клиент не может однозначно интерпретировать «арт не найден» | Major | Зафиксировать контракт: пустое тело = «не найден»; поведение клиента при таком ответе |
| F-05 | AMB | API-5 | Правило имени файла «{время}_{оригинальное имя}» не описывает кириллицу, пробелы, спецсимволы, очень длинные имена | Minor | Описать нормализацию имён либо явно принять as-is |
| F-06 | INC | ТЗ в целом | Отсутствуют нефункциональные требования: производительность, лимит размера файла, безопасность | Major | Запросить NFR у заказчика (эскалация E-4) |
| F-07 | INC | ТЗ в целом | Отсутствуют критерии приёмки/DoD для функций раздела 1.2 | Minor | Закрывается настоящим конвейером: AC формируются на этапе 2 |
| F-08 | INC | Q-1, Q-2, Q-3 | Три открытых вопроса без сроков решения влияют на архитектуру (сохранение данных, ОС, нестабильность ленты) | Major | Эскалации E-1…E-3; до ответа — допущения A-1, A-7, A-1 |

Противоречий (CONTRA) **не выявлено**. Ближайший кандидат — расхождение кодов ответов API со стандартом HTTP (200+null вместо 404, OS-2/OS-12) — классифицирован как AMB контракта (F-04), поскольку ТЗ фиксирует поведение as-is и внутри себя согласно.

## Допущения (assumptions)

| ID | Допущение | Основание |
|---|---|---|
| A-1 | Вероятность ошибки ленты ≤ 35%; клиент обязан повторять запрос и отобразить ленту без ошибки пользователю | F-01, Q-3 |
| A-2 | 255 символов — включительно; превышение отсекается клиентом (сервер валидации не имеет, OS-4) | F-02 |
| A-3 | Теги — строка через запятую; поиск регистрозависим, по вхождению подстроки (as-is) | F-03 |
| A-4 | Пустое тело 200 = «арт не найден»; клиент показывает «арт недоступен» | F-04 |
| A-5 | Имена файлов не нормализуются (as-is); кириллица/пробелы проверяются тестом | F-05 |
| A-6 | Ограничений типа/размера файла нет (as-is, OS-5); клиент ограничивает выбор файлов сам | F-06 |

## Эскалации (вопросы заказчику)

| ID | Вопрос | Допущение до ответа |
|---|---|---|
| E-1 | Сохранение данных между перезапусками? (Q-1) | Не требуется: стенд учебный, чистый старт — норма (A-7) |
| E-2 | Перенос на Linux-хранилище? (Q-2) | Не планируется: Windows-окружение |
| E-3 | Нестабильность ленты — постоянная характеристика? (Q-3) | Да, штатная (A-1) |
| E-4 | NFR: производительность, лимиты файлов, безопасность | Ограничений нет (A-6); лимиты на стороне клиента |

## Вердикт QG-1: **PASS**

Обоснование: 100% требований распределены (28 позиций реестра); CONTRA уровня Critical — 0; все AMB/INC снабжены допущениями и эскалациями. Конвейер продолжается на этап 2.
