# ArtCase — агент анализа требований и проектирования тестирования

Учебный проект (курс QAI): проектирование AI-агента, который по требованиям из Confluence выполняет конвейер «анализ требований → проектирование задач Jira → проектирование тест-модели для TMS» с контролем качества на каждом этапе.

Пакет документации спроектирован и продемонстрирован на реальном проекте **ArtCase** — тренажёре для обучения мобильных тестировщиков (галерея артов, Spring Boot backend). Требования: Confluence, пространство `ARTCASE`, дерево «ArtCase — Техническое задание» (v2.0, as-is).

## Состав пакета

| Файл | Назначение |
|---|---|
| `agent_instruction.md` | Системная инструкция агента: роль, конвейер, правила, Quality Gate, формат итогового отчёта |
| `skills/requirement_review.md` | Скилл анализа требований: противоречия, неоднозначности, полнота |
| `skills/task_design.md` | Скилл проектирования задач Jira (User Story, Gherkin, трассировка) |
| `skills/test_design.md` | Скилл проектирования тест-модели для Test IT (позитивные/негативные/граничные, DDT-параметризация) |
| `artifacts/01_requirement_review.md` | Результат этапа 1 — ревью ТЗ ArtCase (реальный прогон) |
| `artifacts/02_task_design.md` | Результат этапа 2 — бэклог Jira для ArtCase (реальный прогон) |
| `artifacts/03_test_design.md` | Результат этапа 3 — тест-модель Test IT для ArtCase (реальный прогон) |
| `artifacts/final_report.md` | Итоговый отчёт агента: проблемы, метрики, вердикты Quality Gate |

## Конвейер агента

```
Confluence (ТЗ ArtCase)
        │
        ▼
┌─────────────────────┐   FAIL → отчёт о блокерах и эскалациях
│ 1. requirement_review│──────────────────────────────────────► заказчику
│    ( CONTRA / AMB /  │
│      INC + вердикт ) │
└─────────┬───────────┘
          │ PASS (Quality Gate 1)
          ▼
┌─────────────────────┐   FAIL → доработка с эскалацией
│ 2. task_design       │──────────────────────────────────────► назад на этап 1
│    ( Jira: Epic →    │
│      Story + Gherkin)│
└─────────┬───────────┘
          │ PASS (Quality Gate 2)
          ▼
┌─────────────────────┐   FAIL → доработка бэклога
│ 3. test_design       │──────────────────────────────────────► назад на этап 2
│    ( Test IT: +/-/   │
│      граничные, DDT )│
└─────────┬───────────┘
          │ PASS (Quality Gate 3)
          ▼
   final_report.md  (проблемы + метрики + трассировка)
```

## Использованные правила и паттерны

- **Правила**: работа только с источником (as-is, без выдуманных требований); сквозная нумерация и трассировка REQ → TASK → TEST; обязательная фиксация каждого дефекта с ID, типом, серьёзностью; критерии Quality Gate между этапами.
- **Паттерны**: role prompting, input/output contract (фиксированный вход/выход этапа), few-shot примеры, self-check (самопроверка по чек-листу), quality gate, assumption-based design (проектирование от допущений при открытых вопросах), эскалация вместо угадывания.

## Как подключить к opencode

Скиллы переносимы: содержимое `skills/*.md` можно разместить как `~/.config/opencode/skill/<имя>/SKILL.md` (или `.opencode/skill/` проекта), а `agent_instruction.md` — в `AGENTS.md` проекта. Для доступа к Confluence используется MCP-сервер `mcp-atlassian` (docker), см. `agent_instruction.md`.
